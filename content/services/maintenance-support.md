Launch is not the end of the product. OS versions move, stores change policy, and users find the paths you did not QA. We stay on as the team that already knows the codebase.

We also analyse the app. We look at how people use it, whether there are bugs or issues, and come back with improvements. You can focus on everything else. We keep improving the product.

That can be a retainer (planned releases, monitoring, dependency updates) or on-demand work when something breaks. Either way you are not explaining the project from scratch to a new vendor.

## What we cover

- How people use the app, bugs, issues and improvements
- App Store and Play Store releases
- Flutter, plugin and OS upgrades
- Bugfixes and small features
- Crash and performance follow-up
- A named team, not a rotating ticket queue

If we built the app, maintenance is the natural next step. If someone else built it, we start with a read of the repo and an honest list of what is safe to touch.
